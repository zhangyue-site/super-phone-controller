# 提示音与 ADB 恢复进展（2026-10-21）

## 已实现

有效点击60ms短音；开始收音240ms上扬双音，完成后才开麦克风；停止90ms低音；执行成功上扬双音、失败下降双音。任务完成音以 dialogue 成功状态为依据，不能用点击音代表手机执行完成。全部复用音量0–100与静音，设置保存到NVS；解除静音和调节音量用当前音量反馈。静音时不播报、不响提示音，仍能收音、看屏幕。

voice worker 独占 codec；录音/忙碌期间不补播普通点击或试听，停止先撤销任务和当前播放。增加USB诊断 AUDIO、AUDIO UP/DOWN/MUTE/TEST/CLICK，便于实机检查，不发送手机指令。

- ESP-IDF5.5 USB-local/NCM构建成功，外接实体按键关闭。
- 原板整片8MB Flash备份完成，SHA256 `c704d5778ba6a77349e7e1c1072e2d599d992ed2e44cd092b55917fef61dbb81`，备份位于忽略的private-backups目录，不上传。
- 核对实际分区及此前运行ota_1，仅写0x360000应用；esptool报告 Hash of data verified，保留NVS、assets和启动数据。
- Mac USB识别同一控制板PID4041的新NCM+CDC描述符；用户允许配件后串口恢复，VERSION读回2026.10.21-feedback，首页page=5。Mac获得192.168.77.2；修正SDK默认DNS fallback后，实际DHCP响应不再包含DNS或router。此对端为Mac，不是手机。

- 首页新增整条标题区声音设置入口，生成预览已目视检查，新增触摸命中测试通过。

## 待用户配合与待测

最终首页声音入口版已编译并准备刷入，硬件人工触摸和声音听感仍待用户确认。音量极值和重启保存已由串口实板确认；静音是否实际无声、试听音质、连续对话及手机操作停止仍需听感及端到端测试。SDK codec重新配置时会记录禁用未启用I2S通道的日志；当前codec打开、录音取样成功，仍需人耳确认无卡顿。

建议用户准备：控制板、数据线及一台本人授权的Android测试手机（不要求小米）。先测试屏幕设置中的音量减/加、静音、解除静音和试听，检查点击不重复触发。手机端到端测试必须接入正确主机硬件并完成首次USB调试授权。

## ADB 重启恢复

当前固件仍是NCM+TCP5555路线；手机重启免电脑恢复尚未解决。用户已选不装App、Wi-Fi关闭、允许USB角色/供电改造。已形成 [接口改造与验收说明](../usb-host-recovery-2026-10-21.md)，明确5V受保护供电、USB角色、UART调试、标准ADB传输和移动数据TLS隧道。主机硬件尚未改造，标准USB ADB Host驱动尚未实现，当前没有目标手机可用于重启实测。

## 短提示音听感反馈与修正

用户确认：触摸页面可切换、长语音试听可播，但短提示音听不到。定位现有play_pcm在write入I2S DMA后立即mute/close，未给codec/PA预热、未排空队列；这与短音被截断一致，仍须用户听感复核。新增100ms时钟静音预热与768帧静音尾部，推空4×128帧DMA队列；STOP按每256帧检查取消，跳过剩余尾部。区分实际写入失败与用户静音/音量归零，后者不改变任务成功结果。新增DMA队列模型回归测试，17项host测试通过，ESP-IDF构建通过。

## 屏幕与实体键按下反馈

用户确认两种都要。将有效屏幕按钮反馈移到DOWN边沿（刷新/画面epoch不匹配不接受普通按钮；STOP单独处理）；实体键在消抖后新DOWN反馈。删除释放/语音worker启动时的重复点击音，保留音量0恢复与解除静音时的反馈。普通取消保留正在播放的按下短音，STOP仍强制中断；开始录音前由同一worker完成短音，避免录入自身提示。新增按下、持续按住、释放、再次按下的边沿回归测试。17项host测试与编译通过。快速连点在单槽提示邮箱中可能合并，不保证每次快速触点都单独播放；避免积压迟到提示。人工触摸及实体键听感待确认。

## 响度复测（尚待最终人耳验收）

用户再次报告屏幕、实体键两种提示音均未听到。读取实际事件和播放日志证明按下已触发、PCM完成；在同一次输出中先静音1500ms再播放同频60ms/1000ms对比，用户进一步澄清“有声音，就是特别小”。因此不能把DMA输出成功等同于可听响度，也不能仅将此前问题归因于截断。

短音实板合成峰值原为5000，默认volume60映射约-20dB；本次将短音峰值统一提高至16000，约+10.1dB，保留淡入淡出、频率和时长，音量与静音路径不变，长语音资产不变。峰值仍小于int16最大值。新增峰值和播放耗时日志，波形测试检查peak>12000且<=16000，17项host测试及固件编译通过。临时长短对比PROBE代码未保留在产品固件。用户当前设置为volume80、未静音，未强制恢复默认60。最终听感仍待用户确认。

## 实际音频链路定位与同款 GitHub 对照

此前响度增强并未通过用户验收；用户澄清长语音同样勉强可听，喇叭已连接。不能仅依据驱动OK报告已修复。

参考同款V2的厂家示例、78/xiaozhi-esp32 的 Es8311AudioCodec、LucaCevasco/pietro-computer 的 audio.c。确认引脚一致；IN_OUT句柄本身合法，Pietro同样使用IN_OUT，不能把分离句柄直接认定为修复。参考实现有保持codec打开、应用控制PA、显式reset保持等差异，本轮未将这些差异一起改入。

读取ES8311寄存器与GPIO实物数字pad：播放时42低、46高、09=0C、31=00、12=00、01=3F；volume100对应32=B3（-6dB），I2C读回均成功。闭合后46低、31=60、32=00、12=02、01=00。验证了设置写入，但仍不代表声学输出。

使用仅保留统计、不保存/上传录音的 AUDIO AUDIT：相同1kHz测试音下，PA低时左麦克风1kHz幅度2.2、PA高时20922；右通道DAC参考两次均15146。用户确认PA高那次声音明显。由于该实验还包含长音与RX读取，继续单变量验证：正常短音仍用原PCM/句柄/音量且不读取RX，仅改为DAC稳定静音100ms后开启PA、再静音300ms，随后发60ms短音。用户重播后明确回复“三声都清楚”。支持功放启用顺序是本次可听性关键差异，不再仅归因为PCM幅度。

当前保留该已验收顺序；任意单指触摸DOWN均请求短反馈，页面刷新与无按钮命中不再阻止“收到触摸”反馈，具体动作仍遵守画面epoch/刷新状态规则。新增touch_down/up原始坐标及按压时长事件，便于核查用户报告的首页命中问题。录音或静音时不混入普通点击，STOP独立优先。

## 用户要求更响后的上限校准

在上述“三声都清楚”版本基础上，短音峰值16000→24000（+3.52dB）；保留6dB硬件补偿，用曲线{0,-44dB},{100,+6dB}使UI100对应DAC0dB（原DAC-6dB），最大数字信号相对增加约9.5dB。峰值24000且DAC不超过unity，保留数字余量；这不是声压测量，不能承诺实际再增加20dB。20dB幅度增量需要10倍振幅/100倍功率，不能直接叠加而忽略硬件余量。

17项host测试和ESP-IDF5.5编译通过；代码静态复核无阻断。最终更响版本仍待用户确认响度、是否失真，以及屏幕加减、首页和实体按下的实际体验。ADB USB Host硬件/驱动与手机重启测试仍未完成。
