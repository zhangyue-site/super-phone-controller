## 优先协作的两个问题

### 1. 蓝牙连接错误 133 与恢复

现场出现过 `FlutterBluePlusException | connect | android-code: 133 | ANDROID_SPECIFIC_ERROR`。当时 MediaProjection 仍有效，蓝牙开启但 GATT 没有连接。通过助手“释放手机中转，保留屏幕共享”再“恢复本机手机中转”，实际恢复连接、服务发现和 MTU 协商，无需断电。

这只证明该恢复路径有效，尚未证明错误 133 的唯一根因。请优先检查失败连接清理、异步恢复并发和旧服务所有权，不把无限重试或强制断电作为解决方案。

相关代码：`app/lib/ble_ota_service.dart`、`app/lib/usb_target_screen.dart`、`app/lib/target_session.dart`、`app/lib/gateway_recovery.dart`。

验收：模拟连接失败与取消交错；只能有一个有效连接；STOP、拔插、所有权变更后不恢复旧任务；在实机重复恢复且保留有效共享，错误应在对应阶段恢复后清除。

### 2. 实体键盘模式下的中文搜索

已取得 USB 拼音输入回执，但部分输入法把拼音直接提交为拉丁字母，未取得中文候选。一次性维护切换到已启用的 Gboard 后，画面显示小型“拼”提示与底部键盘选择器；规划器反复点击设置搜索栏，尚未进入已核验的中文输入闭环。

当前普通视觉观察仅有任务与单张画面，首个文字动作前缺少成功导航步骤上下文。正在评估加入已 ACK 动作的语义上下文和重复点击上限；这些候选尚未作为已部署修复记录。ACK 不证明焦点，输入法提示也不能单独当作已聚焦证据。

相关代码：`display_service/general_nav.py`、`display_service/general_vision.py`、`display_service/keyboard_navigation.py`、`display_service/keyboard_input.py`。

验收：真实 HID 输入拼音 → 真实共享图定位可见中文候选 → HID 选择 → 新画面显示已提交中文 → 独立核验搜索结果；随后在同一有效共享期间执行第二条任务。不允许用 ADB 输入、合成画面或模型自评替代。
