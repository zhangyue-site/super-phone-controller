# 首帧与连续新帧超时诊断

本次延续提交 b0fc7b1 的新帧等待诊断：保留等待序号、最新序号与画面年龄日志，以及静态画面的合成回归。它不改变动作围栏，不重试或重放输入。

共享授权有效只证明当前能力尚未过期，不证明系统投屏仍运行。Android 1.3.9（46）在现有已认证的空 body 状态请求中附带两个可选状态头：`X-Screen-Interactive` 和 `X-Screen-Keyguard-Locked`。值只允许 `0` 或 `1`，任一系统读取失败则两个头都省略；不包含界面文字、图像或用户身份。

服务端仅接收成对合法状态，使用服务端单调接收时间，以共享票据和设备隔离，五秒后失效，内存最多保存256条。旧客户端或缺失、非法、重复头保持请求兼容，但不沿用旧状态。撤销、换票或设备不符时不得借用状态。

新任务还没有第一帧时，诊断需要独立于真实帧会话的关联；这不会设置真实 screen_session、屏障或输入许可。多个有效票据无法唯一归属时保持未知；真实帧会话存在时始终以它为准。

仅有新鲜证据时区分锁屏与息屏；其他情况明确原因尚未确认，不把授权仍有效说成投屏正常，也不一律要求重新共享或开启实验取样。状态仅辅助解释失败，不能用于绕过系统解锁、开启输入许可或认定操作完成。

验证包含认证状态请求、旧客户端、错误与重复头、有效期边界、设备和票据隔离、撤销、第一帧缺失、多票据冲突及无动作重放。合成测试不替代真实设备验收；新版上报需要安装新版助手后验证。
