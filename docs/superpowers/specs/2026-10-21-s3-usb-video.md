# 现有 S3 安卓 USB 视频研究与实施边界

用户最新决定：现有 Waveshare ESP32-S3 继续作为主控，P4不作为必需条件。ADB只用于ADB Keyboard中文输入，结束恢复原输入法；运行时没有电脑、不使用Wi-Fi、不装手机控制App。

## 核实后的协议事实

- S3能够作为USB Host接收Full-Speed UVC的MJPEG视频。乐鑫 usb_host_uvc 1.0.2列明S2/S3约0.5MB/s与512字节MPS限制；实际帧率、压缩率需要采集源验证。无需在S3上解码H.264，可直接把JPEG帧交给视觉服务。
- 安卓原生USB webcam输出手机摄像头；不能当屏幕截图。AOA定义配件、ADB和HID功能，没有通用屏幕视频接口。
- iPhone S3参考项目以Wi-Fi AirPlay取得H.264，并由手机App解码，USB只发HID。它证明S3可承担中转与鼠标，不证明安卓可以免App、免Wi-Fi、免ADB视频直出。
- 普通USB摄像头描述符或High-Speed HDMI采集卡规格不能证明S3可用。必须取得Full-Speed真实描述符及有效MJPEG屏幕帧。
- 当前现板USB Device固件和USB Host不能占用同一OTG控制器并发。未来若S3 Host接采集器与手机，应使用经验证的USB Hub及AOA HID，同一Host栈管理UVC与ADB接口；不要同时装两套互不兼容的Host栈。

## S3优先的候选硬件链路

手机DP Alt Mode输出 → DP-to-HDMI转换 → 能在USB Full-Speed输出MJPEG的HDMI采集模块 → S3 USB Host → JPEG帧上传106。采集模块负责视频接收/压缩，S3负责转发、屏幕、语音、AOA鼠标和中文输入调度。

此方案不要求P4，但需要额外的视频接收/压缩模块和Host供电接口。现有S3板未包含这些模块。暂未找到已验证符合要求的具体HDMI采集模块，不能按外观/芯片名直接购买。DP输出同时维持手机USB device/AOA角色是单独的关键未决项：普通手机HDMI扩展坞通常让手机当USB host，不能直接连接另一个host。必须验证USB-C PD/data-role协商或专用布线，不能把普通Hub画成已可用接线图。

S3与手机间的网络出口也需独立解决；不允许把现有ADB网络代理宣称为ADB仅输入。当前固件仍有ADB TLS隧道，尚不符合最终ADB输入专用的传输要求。需要USB网络共享或其他已授权网络通路的同角色并发验证；本轮不改动已工作的语音/OTA。

## 已实施

新增tools/check_s3_uvc.py离线描述符检查器：解析USB配置、UVC MJPEG格式/帧间隔、视频IN端点与FS包长；High-Speed、无MJPEG、包长超限和畸形数据拒绝。输出只标记descriptor_candidate，明确screen_source_verified=false、streaming_verified=false，不能作为采集验收。该开发工具不打开USB、不调用ADB，产品运行不依赖它或电脑。

## 必须实际完成后才能开启手机操作

1. 在FS下拿到采集模块描述符和真实手机屏幕MJPEG帧，确认搜索文字可读、帧龄和吞吐。
2. 验证供电、USB-C视频与数据角色、Hub、AOA HID/ADB中文输入和网络出口可并发。
3. 把验证后的UVC Host实现接入S3，统一处理热插拔、STOP、帧失效和HID释放。
4. 实测语音打开微信找李洋、保留结果页、恢复原IME、播报与屏幕停止。
