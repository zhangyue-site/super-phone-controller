# 语音后的手机指令通路

用户确认先完成软件，手机直连实测稍后进行；ADB由用户手动开启，不装App，不启用Wi-Fi，不改USB硬件。

现有语音→106任务邮箱→板端ADB执行→界面验证→TTS通路已存在。本轮修正实机观察脚本：uiautomator在独立进程向/proc/self/fd/1写入不返回XML，改用唯一临时文件、检查成功后cat，并用trap清理；安装Activity输出先过滤组件再截取128项。锁屏和前后台变化仍拒绝操作。

失败通过结构化code反馈至106，由106给出明确中文屏幕/TTS提示，日志只保留步骤、耗时及字节数，不打印界面内容和凭据。手机ADB未开时明确提示需手动恢复5555，而非仅开USB调试即可。旧命令未知结果不重试，STOP不重放。

验证分层：实际手机只读观察兼容性；模型与任务邮箱/实际固件ADB执行器的协议联调；主机回归及固件构建。手机当前Wi-Fi连接只能作为诊断，不能计作无Wi-Fi的板手机直连验收。用户稍后完成直连测试。
