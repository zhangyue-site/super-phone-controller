# WeChat visual navigation and replay skills
User authorizes isolated simulation first: open WeChat, find 李洋, leave search results, never send messages. ADB only type Chinese via existing IME-restoring command. Screen source is user-consented Android MediaProjection, not ADB.

Flow is deterministic policy over visual observations: HID Home -> fresh launcher -> WeChat icon click -> fresh WeChat home -> global-search click -> fresh search input -> Chinese input -> fresh results -> independently verify WeChat search page, exact query and matching contact. Only known semantic target enums (wechat_app/global_search/search_input) can be clicked. No arbitrary LLM tool actions. Unknown screen, crop/rotation/geometry change, stale frame, cancellation, timeout, invalid receipt or unsupported board protocol stops without claiming success. Board requires local HID consent, new absolute USB mouse report with normalized coordinates, strict bounds and press/release sequencing; real Android absolute-pointer compatibility remains hardware acceptance, not proven by simulation. No firmware automatically flashed in this simulation task.

Cloud vision uses existing configured image-capable provider, passed JPEG current turn, structured JSON. Capture post-action frames only after board receipt, discard older/in-flight captures across barrier. Waits bounded. Logs contain stage/frame/command/receipt/verification/AI usage, no raw screenshots or contact text.

Skill save is explicit voice '存为技能', only last verified successful trace per device, scoped durable private database. Group 微信, exact contact-specific task. Replay always Home first. Store strict normalized visual reference fingerprints plus semantic action/bounds; use cached action only when full-frame and target-region comparisons strongly match same geometry. Any mismatch invokes fresh vision; never replay typing from untrusted model. Final result always new vision verification (exact query + contact + result page), so '尽量少用AI' rather than blind zero-AI. Changed/failed/cancelled tasks cannot be saved. No skill can send messages or override allowlist. Simulation records not mixed into production skill store.

App1.0.5+6 retains new icon and OTA; improves full-display consent guidance, capture rotation handling, board capability awareness, remote task status and skill grouping feedback. System shared-app-only capture rejected for coordinate control, users must choose whole display. Show task states separately from upload success. Stop revokes screen session and cancels active turn.

Tests before code: deterministic synthetic phone frames + real mailbox simulated board ACK, full flow, stop/drop/old frames/failed input/final mismatch/no message, valid/invalid skill replay, fewer AI calls and device isolation. Run real vision on synthetic Chinese screen fixture to validate transport only, not claim real phone navigation. Cloud C++ host/IDF and Flutter tests/build; private staged firmware, signed App update with honest hardware limits.

Review refinements: every board ACK, including Chinese input with IME restoration, clears frames and rotates capture barrier. App must echo barrier from previous capture response into future captures. Bind ticket+device+turn+barrier+frame ID, revoke old device screen tickets and cancel old task on screen restart. Final observation is compared with latest bounded-age fresh frame before completion/save; interrupted tasks cannot be saved.
